## 3. Behaviour changes to be aware of
- Backend **refuses to start** without `DATABASE_URL` (with password). Intentional.
- Version is `0.1.1`; existing `/api/v1/health` and `/api/v1` contracts preserved. Added `/api/v1/health/ready` (503 if DB down).
- Error responses now use the `{"error": {...}}` envelope (including 404/405/422).
- Frontend API default is same-origin `/api/v1` (nginx proxy in prod); dev compose sets an absolute URL.
- Dependency downgrades vs `latest` (e.g. React 18.3.1, Vite 5.4.11) for a known-compatible set; not tested.
- Frontend Dockerfile uses `npm ci` when a lockfile exists, otherwise `npm install` (temporary).
- The `internal: true` network + `read_only` + `cap_drop: ALL` hardening is untested; if a container fails to start, these are the first suspects (documented, easy to relax).

## 4. Known limitations / risks
- Everything marked NOT RUN above. Expect possible first-run fixes (pin resolution, a typo, nginx/read-only edge cases).
- No TLS, auth, rate limiting, audit logging, backups, dependency scanning.
- DB password must be URL-safe (use `openssl rand -hex 24`).
- No load testing performed; no scalability claim is made.
